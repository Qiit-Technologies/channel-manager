WESTBURY INN × ANLI CHANNEL MANAGER
TECHNICAL INTEGRATION HANDOFF

Prepared for: Westbury Inn technical team
Property: Westbury Inn — Anli hotel ID 10
Purpose: Connect Westbury Inn to Anli through the Anli Channel Manager.


1. INTEGRATION ROUTING

Westbury Inn connects to the Channel Manager. Do not call Anli PMS endpoints directly.

Westbury Inn → Anli Channel Manager → Anli PMS
Anli PMS → Westbury Inn hotel webhook (direct)

The Channel Manager is the gateway for Westbury Inn's availability and reservation API calls. Separately, Anli PMS sends event notifications directly to the hotel's configured webhook URL; these notifications do not pass through the Channel Manager.

BASE URL
https://channel-manager-8rq4.onrender.com/api/v1

AUTHENTICATION
Protected routes use the x-api-key header. Obtain the Channel Manager API key through the agreed secure credential-sharing process. Use HTTPS and do not put credentials in URLs or logs.

PROPERTY
hotelId: 10
Use this hotel ID for live availability requests. Availability is checked directly against the hotel's PMS inventory using the Anli room-type ID.

If Westbury Inn needs a live check-in status, include a secured status-read endpoint in the integration requirements before relying on it.


2. ANLI PMS → WESTBURY INN HOTEL WEBHOOK (EVENT NOTIFICATIONS)

Anli sends hotel-level event notifications directly to the URL configured for hotelId 10. This is separate from the Channel Manager APIs in Sections 3 and 4. Use the booking API for Westbury Inn-initiated booking reads and writes; the webhook is not a second booking-creation path.

Do not create or update a booking again when receiving a webhook for that same booking. Treat these messages as notifications that Anli state changed, not as commands to Anli.

2.1 CONFIGURATION

Webhook notifications require an enabled hotel-level configuration for hotelId 10 with the Westbury Inn receiver URL, HTTP verb, shared secret, and event allowlist. Provide the receiver URL and use the agreed verb and securely shared secret. Webhook-management API routes are not part of Westbury Inn's integration; do not call them from Westbury Inn.

- Provide the Westbury Inn endpoint URL that will receive Anli event notifications.
- Supported verbs are GET, POST, PUT, and PATCH. POST is the default and is recommended unless Westbury Inn requires another verb.
- Use a strong shared secret and store it securely.
- Configure only the event types Westbury Inn needs. A null/unset event list allows all event types; an empty list allows none.
- Keep this hotel-level webhook separate from channel/integration webhook settings.

2.2 PAYLOAD AND AUTHENTICATION

For POST, PUT, and PATCH, Anli sends this JSON envelope (data fields vary by event):

{
  "hotelId": 10,
  "eventType": "BOOKING_NEW",
  "event": "BOOKING_NEW",
  "timestamp": "2026-11-16T09:00:00.000Z",
  "data": {
    "id": 123,
    "bookingCode": "ANLI-BOOKING-123"
  }
}

Headers include Content-Type: application/json, X-Webhook-Event, and X-Webhook-Timestamp. When a secret is configured, Anli also sends X-Webhook-Signature, an HMAC-SHA256 hex digest of the exact JSON payload using the shared secret, and X-Secret-Key. Verify the signature against the exact received payload and do not log or expose the shared secret or signature. For GET, Anli sends the payload as query parameters rather than a JSON request body; use POST so the payload and signature can be verified consistently.

2.3 EVENTS CURRENTLY EMITTED BY ANLI

| Event | Emitted after |
| --- | --- |
| BOOKING_NEW | A reservation is created |
| BOOKING_MODIFY | A reservation is updated |
| BOOKING_CANCEL | A reservation is cancelled |
| CHECK_IN | A guest is checked in |
| CHECK_OUT | A guest is checked out |
| RATE_CHANGE | A room price is changed through the room-price update path |
| AVAILABILITY_CHANGE | A room status is changed or a room is marked out of order |
| TEST | An authorized operator sends a webhook test |

BOOKING_NO_SHOW is listed as a supported event type, but no no-show event is currently emitted. Do not subscribe to or depend on it. AVAILABILITY_CHANGE is not currently emitted just because a reservation is created or cancelled. The event-list endpoint lists names; it does not prove that an event is emitted.

The data object is event-specific. Booking events include booking identifiers and reservation fields; room events contain room and change details. Westbury Inn must handle absent or additional data fields without failing the receiver.

2.4 DELIVERY BEHAVIOR AND DEVELOPER CHECKLIST

- Outbound HTTP delivery runs in the background: the PMS operation does not wait for Westbury Inn's HTTP response. Do not design Westbury Inn's receiver or integration flow to make PMS operations depend on webhook delivery.
- A webhook failure is logged by Anli but is not returned as a PMS operation failure. The current dispatcher has no durable event queue or automatic retry, and payloads have no stable event ID. This is best-effort notification, not guaranteed delivery or an exactly-once feed.
- Validate the HMAC signature, verify hotelId and eventType, return a prompt 2xx response, and process any slower follow-up work asynchronously on Westbury Inn's side.
- Make the receiver safe to process a repeated notification. There is no stable webhook event ID, so use the booking/room identifiers and event data for any applicable duplicate protection.
- Keep the Channel Manager booking API as the authoritative Westbury Inn booking read/write path. Do not rely on the webhook as the only record of a booking or as a substitute for reading booking state.
- In the agreed test environment, configure hotelId 10, send a TEST event, verify method, headers, signature, and envelope at Westbury Inn, then exercise representative booking, check-in/out, rate, and room-status actions. Confirm the configured event allowlist includes the events being tested.

x-api-key: {CHANNEL_MANAGER_API_KEY}
Content-Type: application/json

Swagger requires hotelId. Its other documented request fields are fullName, email, phoneNumber, status (PENDING or CONFIRMED), amount, numberOfGuests, currency, startDate, endDate, and cancelReason.

4.5 CANCEL BOOKING

POST {BASE_URL}/channel-manager/bookings/{bookingCode}/cancel
x-api-key: {CHANNEL_MANAGER_API_KEY}
Content-Type: application/json

{
  "hotelId": 10,
  "reason": "Cancelled by Westbury Inn"
}

hotelId is required; reason is optional. The Channel Manager forwards the cancellation to Anli PMS.

Swagger documents HTTP 200 but does not define a response body.

4.6 GENERATE INVOICE PDF

POST {BASE_URL}/channel-manager/bookings/{bookingCode}/invoice
x-api-key: {CHANNEL_MANAGER_API_KEY}
Content-Type: application/json
Accept: application/pdf

{
  "hotelId": 10
}

Success returns an invoice PDF generated from the current PMS folio. The Channel Manager must have PMS forwarding enabled for this route.

Swagger documents HTTP 200 with Content-Type: application/pdf and a binary response body.
