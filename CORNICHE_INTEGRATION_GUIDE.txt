CORNICHE × ANLI CHANNEL MANAGER
TECHNICAL INTEGRATION HANDOFF

Prepared for: Corniche technical team
Property: Corniche — Anli hotel ID 8
Purpose: Connect Corniche to Anli through the Anli Channel Manager.


1. INTEGRATION ROUTING

Corniche connects to the Channel Manager. Corniche must not call Anli PMS endpoints directly.

Corniche → Anli Channel Manager → Anli PMS
Anli PMS → Anli Channel Manager → Corniche

The Channel Manager is the integration gateway. It receives channel booking notifications, forwards supported booking operations to the PMS, and provides channel availability and rate data. Corniche will receive only Channel Manager API connection details.

BASE URL
https://channel-manager-8rq4.onrender.com/api/v1

AUTHENTICATION
Protected routes use the x-api-key header. Anli will provide the Channel Manager API key securely. Use HTTPS and do not put credentials in URLs or logs.

PROPERTY
hotelId: 8
Use this hotel ID for live availability requests. The live availability endpoint does not require a channel integrationId or room-type mapping.


2. CORNICHE → CHANNEL MANAGER: BOOKING WEBHOOK

Corniche sends booking events to the Channel Manager webhook route:

POST https://channel-manager-8rq4.onrender.com/api/v1/channel-manager/webhooks/CORNICHE
Content-Type: application/json

Current handler requires hotelId and accepts a channel webhook body. The Corniche adapter expects event_type, timestamp, and data. For a reservation, use this structure:

{
  "hotelId": 8,
  "event_type": "reservation",
  "data": {
    "reservation_id": "CORN-987654",
    "property_id": "CORNICHE-PROP-008",
    "room_type_id": 12,
    "check_in": "2026-12-10",
    "check_out": "2026-12-12",
    "rooms": 1,
    "number_of_guests": 2,
    "amount_paid": 0,
    "guest": {
      "name": "Jane Doe",
      "email": "jane@example.com",
      "phone": "+2348012345678"
    }
  }
}

SUCCESS RESPONSE — HTTP 202
{
  "status": "accepted",
  "message": "Webhook processed successfully"
}

The adapter reads:
- event_type: reservation, cancellation, or modification.
- data.reservation_id, booking_id, or id as the channel reservation reference.
- data.room_type_id, check_in, check_out, rooms, number_of_guests.
- data.guest.name, data.guest.email, data.guest.phone or phoneNumber.
- data.amount_paid and data.outstanding when available.

The handler responds HTTP 202 when it accepts the webhook. The current webhook route does not declare API-key authentication; Anli must agree and configure the production webhook security method before go-live.

All routes in this section are Channel Manager routes. They do not expose Anli PMS endpoints.

3.2 LIVE AVAILABILITY AND RATES

GET {BASE_URL}/channel-manager/availability/live?hotelId=8&roomtypeId=15&checkInDate=2025-06-01&checkOutDate=2025-06-05
x-api-key: {CHANNEL_MANAGER_API_KEY}

Required query fields: hotelId, roomtypeId, checkInDate, and checkOutDate. Dates use YYYY-MM-DD; check-in is inclusive and check-out is exclusive. This endpoint checks live PMS availability and rates for the requested room type and stay. It does not require an integrationId or a channel room-type mapping.

roomtypeId is the room type ID in Anli PMS, not a channel-specific mapping. The existing /channel-manager/availability endpoint returns stored channel records; use /channel-manager/availability/live for this direct date-range check.

4.3 CREATE BOOKING IN PMS THROUGH CHANNEL MANAGER

POST {BASE_URL}/channel-manager/bookings
x-api-key: {CHANNEL_MANAGER_API_KEY}
Content-Type: application/json

**Contract to confirm with Anli before Corniche implements this request:** the Channel Manager controller currently declares two `POST /channel-manager/bookings` handlers with different request contracts. One expects flat fields such as bookingCode, fullName, email, startDate, endDate, hotelId, and roomTypeId. The other uses the external-booking DTO, requiring hotelId, roomTypeId, checkInDate, checkOutDate, guest, totalPrice, externalConfirmId, and source. These contracts are incompatible, and the checked-in OpenAPI file does not describe this route. Anli must select and publish one contract before Corniche sends create requests.

The flat-field handler maps aliases including name/guestName, phone, checkInDate/checkIn, checkOutDate/checkOut, roomTypeId/roomType, totalPrice/bookingAmount, source/status, propertyRef, and externalConfirmId. It defaults amountPaid to the reservation amount when omitted, and does not forward currency. Do not rely on these details until Anli confirms which handler is active and aligns its Swagger schema and implementation.

{

4.4 UPDATE BOOKING

PUT {BASE_URL}/channel-manager/bookings/{bookingCode}
x-api-key: {CHANNEL_MANAGER_API_KEY}
Content-Type: application/json

hotelId is required. The documented request fields are fullName, email, phoneNumber, startDate, endDate, amount, numberOfGuests, status (PENDING or CONFIRMED), and cancelReason. The request mapper also accepts checkInDate/checkOutDate, bookingStatus, and voidReason as aliases.

The Channel Manager forwards supported updates to Anli PMS. To cancel, use the dedicated cancel route. Room type, room number, currency, source, amountPaid, and OTA reference are not changed by this update mapping.

EXAMPLE REQUEST
{
  "hotelId": 8,
  "fullName": "Jane Doe",
  "email": "jane@example.com",
  "phoneNumber": "+2348012345678",
  "startDate": "2026-12-11",
  "endDate": "2026-12-13",
  "amount": 320000,
  "numberOfGuests": 2,
  "status": "CONFIRMED"
}

SUCCESS RESPONSE — HTTP 200
{
  "bookingCode": "ANL-123456",
  "oreonForwarded": true
}

4.5 CANCEL BOOKING

POST {BASE_URL}/channel-manager/bookings/{bookingCode}/cancel
x-api-key: {CHANNEL_MANAGER_API_KEY}
Content-Type: application/json

{

SUCCESS RESPONSE — HTTP 200

4.6 GENERATE INVOICE PDF

POST {BASE_URL}/channel-manager/bookings/{bookingCode}/invoice
x-api-key: {CHANNEL_MANAGER_API_KEY}
Content-Type: application/json

{

Body: PDF binary data (not JSON).


5. CHECK-IN AND CHECK-OUT

Check-in and check-out are performed by Anli PMS staff. Corniche must not change guest check-in status through the Channel Manager.


6. IMPORTANT IMPLEMENTATION STATUS

- Corniche should use the Channel Manager base URL and routes above; do not call Anli PMS endpoints directly.
- Reservation create, update, cancellation, and invoice requests pass through the Channel Manager. Anli must enable and test its internal PMS forwarding configuration.
- Live availability and rates for a requested hotel stay are fetched from the PMS through the Channel Manager. This call does not use a channel integrationId or room-type mapping. The rate-plan endpoint remains a separate read of stored Channel Manager data.
- The current Corniche adapter has a hard-coded outbound API base URL that Corniche has not confirmed. Anli must correct that endpoint and validate the Corniche API contract before enabling Channel Manager pushes of availability, rates, or other updates to Corniche.
- The current Corniche webhook adapter forwards reservation creation to PMS, but its cancellation and modification event handlers do not currently forward those changes to PMS. Anli must complete and test those event flows before Corniche uses them for live booking updates.
- The Channel Manager webhook route currently has no API-key guard. Anli and Corniche must agree on an authentication/signature or network allowlist mechanism before exposing it for production traffic.
- Anli will provide the final production credentials and confirm the applicable API routes before Corniche begins testing.

Corniche and Anli should test room mapping, webhook delivery, create/read/update/cancel, invoice PDF delivery, duplicate handling, and failure responses in an agreed test environment before production cutover.
